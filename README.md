# KrolikGuard — Telegram-бот для Vercel

Это серверная версия бота. Сайта, веб-панели и постоянного polling-процесса здесь нет. После подключения Vercel принимает запросы Telegram на /webhook, компьютер можно выключить.

## Что сделать на компьютере друга

1. Распакуйте архив. Замените содержимое репозитория, подключённого к проекту Vercel, файлами из этой папки. app.py, requirements.txt и vercel.json должны лежать в корне репозитория. Не загружайте старый скрипт с открытым токеном.
2. Vercel → проект → Settings → Build and Deployment: Framework Preset = Flask; Root Directory = корень репозитория (если файлы загружены в корень). Не задавайте Output Directory и свою Build Command. Сделайте Redeploy после изменения настроек и переменных.
3. Подключите PostgreSQL: Storage → Marketplace → Neon или другой Postgres-провайдер → подключить к проекту. Выберите подходящий вам тариф. Код читает DATABASE_URL, а также POSTGRES_URL. Используйте pooled connection string с SSL из панели провайдера. SQLite и JSON-файлы не подходят для хранения данных на Vercel.
4. Vercel → Settings → Environment Variables → добавьте переменные ниже в Production. Токен вводите только там, а не в исходник и не в чат. После этого сделайте Production Redeploy.
5. Остановите старый бот, запущенный на компьютере. В Settings → Deployment Protection убедитесь, что production-адрес /webhook доступен Telegram без входа в Vercel. Защита самого обработчика уже встроена: секретный заголовок Telegram. Не отключайте защиту других проектов.
6. Запустите CONNECT_BOT.cmd на компьютере друга. Укажите адрес production-проекта и тот же WEBHOOK_SECRET, который сохранили в Vercel. Этот файл не требует установки библиотек; нужен Python. Он создаёт таблицы, подключает webhook и проверяет адрес в Telegram.
7. Отправьте боту /start в Telegram. Для проверки оплаты нажмите кнопку покупки PRO и завершите оплату Stars самостоятельно. Компьютер после подключения можно выключить.

## Переменные Vercel

| Переменная | Значение |
| --- | --- |
| BOT_TOKEN | Новый токен из BotFather. Старый токен из исходника перевыпустите через /revoke. |
| WEBHOOK_SECRET | Случайный секрет, 32–256 символов: буквы, цифры, _ и -. Запустите GENERATE_SECRET.cmd для генерации. |
| DATABASE_URL | Строка PostgreSQL с SSL, если интеграция не заполнила DATABASE_URL или POSTGRES_URL автоматически. |
| SITE_URL | Production-адрес вида https://имя-проекта.vercel.app без / в конце и без пути. |
| OWNER_ID | Telegram ID владельца, по умолчанию 5224030424. Для бота друга проверьте, что это нужный владелец. |
| BOT_USERNAME | Имя бота без @, в исходном проекте hytgdrt_bot. |
| PRO_STARS_PRICE | Необязательно: стоимость PRO на 30 дней, по умолчанию 100. Не меняйте цену при неоплаченных счетах. |

## Команды

/start — меню; /buy — счёт Stars; /status — подписка; /help, /terms, /paysupport — команды, условия и поддержка.

/ban, /unban, /mute 30m, /unmute — ответом на сообщение в группе, нужны PRO и права администратора. Бот также должен быть администратором с правами удаления и ограничения участников. Автомодерация проверяет текст и подписи к медиа. Предупреждения и ограничения учитываются отдельно для каждого чата.

Владелец: /grant ID, /revoke ID. В личных сообщениях: /logs — последние 15 событий, /stats — активные подписки и полученные Stars. Оплата не предоставляет обычному участнику права администратора чата.

## Если бот не отвечает

- Откройте https://имя-проекта.vercel.app/health: ожидается JSON с ok=true. Ошибка базы означает, что нужно проверить PostgreSQL и переменные Production.
- Ошибка 404: файлы или Root Directory указаны неверно. app.py должен быть точкой входа Flask.
- Ошибка 403 в CONNECT_BOT.cmd: проверьте WEBHOOK_SECRET (не BOT_TOKEN) и доступ production-развёртывания без авторизации Vercel.
- После изменения переменных требуется Redeploy, затем повторный запуск CONNECT_BOT.cmd.
- Ошибки Telegram пишутся в Runtime Logs Vercel и в /logs владельца без токенов. Коды 400/403 при модерации часто означают отсутствие у бота нужных прав.
- Если другой скрипт вызывает deleteWebhook или getUpdates с этим же ботом, остановите его и снова запустите CONNECT_BOT.cmd.
- Чтобы читать сообщения в группе, выдайте боту права администратора. При необходимости проверьте /setprivacy в BotFather.

## Что исправлено

Webhook вместо бесконечного потока; внешняя постоянная база PostgreSQL; создание таблиц с блокировкой между экземплярами сервера; короткие сетевые таймауты; ограниченные по времени соединения БД без локального пула; проверка секрета Telegram; защита от повторных update_id и payment charge ID; проверка валюты, суммы и назначения оплаты; подтверждение pre_checkout_query; атомарная запись оплаты и выдача PRO; продление от текущего срока; подтверждение оплаты после фиксации в БД; повтор временных ошибок; постоянные ошибки Telegram не блокируют очередь; права администратора проверяются отдельно от PRO.

Для последовательной обработки предупреждений и оплаты webhook подключается с max_connections=1. Сервер не удерживается постоянным процессом. Он отвечает на запросы Telegram; возможна задержка при холодном старте Vercel или пробуждении базы.

## Проверка

Автоматические проверки: python -m pip install -r requirements.txt, затем python -m unittest -v test_server. Используется временная SQLite и имитация Telegram API. Реальный PostgreSQL, настройку аккаунта Vercel и оплату в Telegram нужно проверить после подключения. Токенов в архиве нет.
